# Hearing Store CRM – Audit Report (22 Oct 2026)

Scope: the local development copy at `E:\Rebuild CRM` (branch `master`, HEAD `fb9b03f`).
Production was not touched: no SSH, no deploy, no production database or services.
This is a code audit with local testing, not a security certification.

## 1. Environment and boundary

| Check | Result |
|---|---|
| App `.env` | `APP_ENV=local`, `APP_DEBUG=true`, DB host is the local machine (127.0.0.1/localhost), database `crm_local` |
| Test database | Disposable `crm_audit_test` on the local MariaDB (config `phpunit.audit.xml`, `DB_DATABASE` forced). `crm_local` was never used for tests |
| Mail | `MAIL_MAILER=log` locally, `array` in tests |
| SMS | **Real SSL Wireless URL and token are in the local `.env`** and the test config does not switch SMS off (see TST-01) |
| Queue / cache | `QUEUE_CONNECTION=database` locally, `sync` in tests |
| Untracked files kept as they are | `_rel/` (93 MB full copy of the app, with its own `.env` and `vendor`), `recovered_chat_history.md`, `phpunit.claude.xml`, `phpunit.audit.xml`, three `.bak` views, `resources.zip` |

Versions: Laravel 12.68.0, PHP 8.2.33 (8.2 required), MariaDB 10.4.32, Composer 2, PHPUnit 11.5.
Frontend: Blade + jQuery/AdminLTE assets in `public/assets`; no npm/Vite build exists, so there is no frontend build to run.

## 2. Inventory

617 routes (31 public), 91 controllers, 121 models, 41 services, 3 jobs, 8 console commands, 0 policy classes
(authorisation is the `permission` gate + `CheckPermission` middleware + per-controller closures), 10 middleware,
149 migrations, 319 Blade views, 58 test files.

Critical workflows: leads → deals → appointments → sales (products with serial numbers / batches, services,
loyalty points, doctor commission) → payments/dues/advances → returns/credit notes → repairs/warranty →
purchases/stock/transfers → ledgers/vouchers/cash-bank book → SMS/marketing automation → reports.
Branch isolation: global scopes (`vendor_filter`, `vendor_relation_filter`) + `Helper::headOfficeOnly`.

## 3. Findings

Severity: Critical / High / Medium / Low. Confidence: Confirmed (read in code, and where possible reproduced in a test) or Hypothesis.

### Security

| ID | Sev | Conf | Finding | Evidence | Impact | Fix | Tests |
|---|---|---|---|---|---|---|---|
| SEC-01 | **Critical** | Confirmed | File uploads saved under `public/` keep the browser's file extension, and four forms have no file-type rule at all | `app/Classes/Helper.php:71-82` (`getClientOriginalExtension()` → `public_path()`); no rule for `image` in `EmployeeController.php:104-113,~150`, `MedicineController.php:142-157,199`, `logo`/`favicon` in `SettingController.php:51-60`. Same extension pattern in `RepairController.php:1446,1541` and `PurchaseReturnController.php:624` (these do have a `mimes` rule, but a file that passes the content check can still be saved as `.php`) | Any staff user who can add an employee or medicine can upload `x.php` and run code on the server (remote code execution, full database access) | Validate as images; save with the extension detected from the content, from an allow-list; never the client name | Upload a `.php` file → rejected; upload a PNG named `.php` → saved as `.png` |
| SEC-02 | High | Confirmed | Two sales lists have no permission check | `routes/web.php:326,337` → `SaleController@dueList`, `@saleList` (only `auth`) | Any logged-in user (e.g. a receptionist with appointments only) can read every invoice of their scope with patient names and amounts | Add `permission:` middleware matching the screens that use them | A user without sales permissions gets 403 |
| SEC-03 | High | Confirmed | Stored XSS in quotations | `ProposalController.php:226,446` saves `content` straight from the request; `resources/views/admin/proposal/show.blade.php:697` prints it with `{!! !!}`. | SEC-04 | Medium | Confirmed | A branch user can file a quotation under another branch | `ProposalController.php:221,437-438` take `vendor_id` from the request | Cross-branch data, wrong branch reports | Branch users always get their own branch | Branch user posting another `vendor_id` keeps own branch |
| SEC-05 | Medium | Confirmed | Dependency advisories | `composer audit`: league/commonmark 2.10.0 (High: GFM table DoS; Medium: raw-HTML bypass), symfony/http-foundation 7.4.17 (ReDoS in Cache-Control), symfony/yaml 7.4.17 (recursion crash), laravel/framework 12.68.0 (Low: XSS on debug page only) | DoS through crafted headers; markdown not used by user input as far as found | Patch-level update of commonmark and the two symfony packages; framework advisory only matters with `APP_DEBUG=true` (must be false in production) | `composer audit` clean for the patched packages |
| SEC-06 | Low | Confirmed | Resource routes point at controller methods that do not exist | `setting` (index/store/show/edit/destroy), `income` (edit/update), `customer-return` (create/edit/update), `manufacturer-return` (create/edit/update), `sale-returns` (edit/update); no view links to them | 500 errors instead of 404; noise in logs | Limit each `Route::resource` to the methods that exist | Route list check |

## 8. Production deployment checklist (for you to run; nothing here was done)

Before
- [ ] Commit the changes; deploy only from a clean commit (`git status` empty apart from known untracked files).
- [ ] On the server: confirm PHP ≥ 8.2, `APP_ENV=production`, `APP_DEBUG=false`, HTTPS, web root = `public/`.
- [ ] Check upload folders for scripts already there: `find /var/www/crm/public/file /var/www/crm/public/uploads -type f ! -iname '*.jpg' ! -iname '*.jpeg' ! -iname '*.png' ! -iname '*.gif' ! -iname '*.webp' ! -iname '*.ico' ! -iname '*.pdf'` – anything listed must be reviewed before deploying.
- [ ] Block PHP in upload folders at the web server (e.g. nginx `location ~* ^/(file|uploads)/.*\.php$ { deny all; }`).
- [ ] Off-site backup of the database and `public/file`, `public/uploads`, `storage/app` (the deploy script also takes a pre-deploy dump and stops if it is too small).
- [ ] If you have a staging copy: deploy there first and repeat the checks below.
